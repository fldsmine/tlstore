## Project Overview

The transcript clarifies that the client intends a combined site with an affiliate/task-earning activity and an app-listing review activity. Working visual identity is TLstore; prototype labels include Appcheck/Fieldtest. Users pay/activate packages, then see jobs; the app-review task presents operator-uploaded app images/listing information and questions inside the platform. A link to the relevant store may be offered, but downloading is optional. Review tasks include a multi-step, reportedly seven-question flow and attention checks. The earning model includes package rewards, referral commissions, ads/engagement jobs, proxy-gated tasks in some cases, balances and scheduled withdrawals. The relationship among subscription purchase, task assignment, returns and task rewards is still too unclear for a reliable estimate.


1. App Trust & Review Intelligence Platform: Where registered users examine applications from Google Play Store, Apple App Store and Samsung Galaxy Store, answer structured questions, and help companies identify scams, misleading advertisements, privacy risks and poor user experiences.
  The system should help companies assess whether apps match developer claims, promotional images are accurate, suspicious behavior/hidden charges/misleading promises exist, personal information is handled responsibly, and real users would trust the app.

## Objectives 

1. Help companies assess whether an app behaves as advertised, its promotional screenshots are accurate, and it presents suspicious behavior, hidden charges, privacy concerns, or poor user experience. 
2. Collect human observations using repeatable questions rather than ordinary ratings. 
3. Present users with app-review tasks and potentially screenshots to inspect, record structured answers, disclosure/attestation, and progress.
4. Offer earning through advertisers ads
5. Users get a Subscription package to enable them earn from the app reviews and ads share.
6. Purchased package his its referral bonuses, earning limit, withdrawals limit. 


## Technology choices and trade-offs

| Mobile | Flutter + Dart
| API | Laravel (current supported PHP release at implementation), REST/JSON, OpenAPI contract 
| Admin | Laravel+livewire rendered admin panel 
| Database | MySQL 
| Cache/queue | Redis-backed queue/cache 
| Auth | Laravel Sanctum-style first-party token/session model;
| API contract | OpenAPI specification, generated/validated client models where practical | Hand-maintained client/server DTOs are flexible but drift-prone. Contract-first provides shared agreement and test fixtures. |
| Testing | Pest/PHPUnit, Laravel feature tests; Flutter unit/widget/integration tests; provider sandbox tests; static analysis/format/lint in CI 
| Deployment | Containerized Laravel API/worker, managed PostgreSQL, private object store; separate dev/staging/prod, CI/CD and secrets manager
